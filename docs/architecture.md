# 系统架构与第一阶段审计

第一阶段的 `client.py` 负责匿名 HTTP、业务 code、限速/超时/重试、请求预算及分页完整性；`parsing.py` 拒绝未知布局与冲突元数据；`probe.py` 留存真实验证证据。现有 103 项测试在扩展前重跑通过。保留入口 `campus-recruitment`，新增系统入口 `campus-manager`。

审计发现：尚无单列表记录数上限、无标准化数据模型与持久层；字段和日期语义无法在云端确认；原有工作尚未提交。已先在功能分支保存基线。扩展只给原客户端增加可选记录数上限，保留其严格重复分页检查及所有既有测试。

数据流：API Client/离线 Fixture → 配置字段映射与时间标准化 → 采集快照 → 岗位评分 → SQLite 增量与历史 → 半开区间冲突 → 公共报告/JSON/CSV → ICS/Google 同步计划。

核心约束：真实映射与日期语义分别标记；不完整快照不删除旧记录；只有明确可信的源状态能取消招聘会。SQLite 保留旧版本、首次发现和最近检查时间。岗位主键包含招聘会、企业和岗位 ID，企业使用自身 ID，名称相同不合并。个人日程使用独立私有文件，只在私有冲突报告中引用。

日历以招聘会 ID 建立一个事件。ICS UID 稳定，内容修改增加 SEQUENCE。Google event ID 使用确定性编码，映射以目标 calendar ID 隔离；写前读取、写后提交映射，重试/中断后可恢复。Google dry-run 不读取授权，也不推进真实同步映射。系统默认不会触发真实网络或日历写入。

公共导出是标准模型字段白名单，不包含原始响应/数据库/私人活动/密钥。默认不把采集数据提交 GitHub。自动化 artifact 只保存公共导出和脱敏执行摘要，状态数据库另存为私有状态 artifact。
